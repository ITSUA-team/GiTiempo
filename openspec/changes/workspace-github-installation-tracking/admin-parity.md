# Admin Settings installation parity checklist

Sources reviewed before implementation: `docs/ui/INDEX.md`, `docs/ui/pages-admin.md` (Settings Page), `apps/admin-web/AGENTS.md`, and the approved `GITiempo.pen` frame **Admin Settings** / **GitHub Workspace Access Card**.

- GitHub Workspace Access retains the approved `SettingsCard`: 620px parent width, 20px card padding, rounded organization rows, the original 16px row padding, 16px row gap, and responsive `Remove` action wrapping.
- Every row remains a workspace organization-policy row: GitHub organization login, `Allowed for this workspace`, and `Remove`. The later user-requested `Install App` button appears beside `Remove` after successful status loading when the organization has no verified association. Absent, suspended, unavailable, and disconnected states qualify; no installation status labels, separate Connect/Check/Disconnect actions, association-only rows, or additional installations card are rendered.
- When the policy list loads and when an organization is successfully added, the client starts in the background the existing setup flow only for allowed organizations with no saved association and only when the current administrator can prove GitHub owner authority.
- The automatic flow uses App-JWT discovery, then immediately completes full verification with a returned candidate. A missing App (404) or any discovery failure leaves the card unchanged and never redirects the browser. Existing verified, suspended, unavailable, and locally disconnected associations are not automatically retried or reactivated.
- Callback values are not displayed. If a callback occurs through existing recovery guidance, Settings sends state and installation ID only to the authenticated completion endpoint and removes both values from the URL afterwards.
- `Install App` uses a small outlined secondary button, row loading feedback, and a wrapping action group; pending manual setup disables other Install App clicks. It verifies an existing candidate directly or navigates in the current tab to GitHub after successful setup reports no installation. GitHub account selection remains subject to callback verification of the intended organization.
- Setup failures use existing toast feedback, including HTTP 409 reconnect guidance for inaccessible installations and HTTP 403 owner-authority failures when installation access is confirmed. The personal connection prerequisite is enforced before setup.
- The approved frame remains the baseline for the card structure. The additional row action is an explicit user-requested change to that baseline; this document does not claim the design file was updated or that the complete post-installation recovery flow passed a browser check. No PrimeVue constraint required a visual compromise.
