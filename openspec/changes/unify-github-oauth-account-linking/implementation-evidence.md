# Implementation verification

Implementation is on branch `unify-github-oauth-account-linking`, based on planning commit `b367b728`. Results below refer to the local uncommitted implementation on 2026-10-08; they are not deployment or live-provider acceptance evidence.

## Boundaries verified

- OAuth account linking and login request `user:email read:org read:project`; organization discovery and policy validation use OAuth. Installation setup uses OAuth membership and server App verification. Private repository/issue/Projects browsing retains personal App credentials. Timer tracking retains workspace installation credentials.
- Identity ownership is globally unique, with separate encrypted credential families and a durable generation outside the deletable identity link. Staged sign-in credentials commit with the refresh session only after handoff redemption.
- Full Disconnect rechecks authoritative Firebase eligibility, removes both personal grant families and identity ownership, and preserves GiTiempo sessions and workspace/history records. Revocation uses the issuing clients' token-specific endpoints; installation credentials are excluded.
- Shared contracts are coordinated with API and both SPAs. Semantic OpenAPI changes are confined to four paths (`/auth/github/callback`, `/github/account/auth-url`, `/github/auth-url`, `/github/connection`) and four schemas: connection status, unlink, organization recovery, and the existing authorization URL response's rejection of extra properties. Status and unlink expose no credentials.
